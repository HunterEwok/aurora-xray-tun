# aurora-xray-tun

VLESS для смартфонов на ОС Аврора 5.x. Одна команда на компьютере ставит на телефон
Xray-core с TUN по вашей ссылке `vless://`, вторая удаляет всё. На телефоне туннель
включается командой `on` и выключается `off`. Пока туннель включён, весь IPv4-трафик
телефона идёт через ваш сервер VLESS.

```sh
curl -L https://github.com/HunterEwok/aurora-xray-tun/releases/latest/download/aurora-xray-tun.tar.gz | tar xz
cd aurora-xray-tun
./setup.sh 'vless://UUID@ваш.сервер:443?...#vps' 192.168.1.50    # поставить
./setup.sh remove 192.168.1.50                                  # удалить
```

Проверено на F+ R570E с Авророй 5.1.5.105 (32-битный armv7hl). В Авроре 5.2 общий тестовый
ключ ОМП занесён в чёрный список установщика, поэтому там пакет нужно подписывать своим
ключом (см. «Ключи подписи»).

## Как это устроено

В Авроре нет аналога VpnService из Android. VPN в «Настройках» добавляется только
плагином connman, а ставить такие плагины может лишь пакет с подписью Extended, которую
ОМП выдаёт по заявке. Поэтому здесь обходной путь:

- Xray-core сам поднимает TUN-интерфейс `xtun0` и маршруты `0.0.0.0/1` и `128.0.0.0/1`.
  Для этого нужен root, то есть режим разработчика.
- Запускать можно только то, что поставил установщик пакетов: `/home` смонтирована с
  `noexec`, а IMA проверяет подпись каждого исполняемого файла даже у root. Поэтому Xray
  упакован в RPM и подписан публичным тестовым ключом ОМП (профиль Regular). Такие
  пакеты телефон принимает только в режиме разработчика.
  Это не приложение для магазина и значка в списке приложений у него нет: проверка
  пакетов требует .desktop-файл и значки, поэтому они в пакете есть, но скрыты.
- Проверка пакетов требует программу, связанную с glibc и экспортирующую `main()`.
  Поэтому Xray собирается с cgo, как PIE, против glibc старше той, что в Авроре.
- Собственное соединение Xray с сервером идёт мимо туннеля маршрутом `/32` через шлюз
  Wi-Fi или мобильной сети. Адрес сервера берётся из публичного DNS через HTTPS.
- DNS-запросы приложений Xray перехватывает и отправляет через сервер (DoH 1.1.1.1 и
  8.8.8.8). Локальные сети (192.168.x.x и другие) ходят напрямую.

## Что нужно

На компьютере (Mac или Linux): `python3`, `ssh`, `curl`. Docker нужен, только если
собирать пакет самому (см. «Собрать самому»).

На телефоне:
- Включённый режим разработчика: «Настройки → Для разработчиков», там же включить
  удалённое подключение (SSH) и задать пароль. Этот же пароль спрашивает `devel-su`.
- Подключение к компьютеру по USB (телефон будет на `192.168.2.15`) или по Wi-Fi.

Сервер: любой сервер VLESS и ссылка `vless://` от него. Поддерживаются:
- `security`: `none`, `tls`, `reality`;
- `type`: `tcp` (`raw`), `ws`, `grpc`, `httpupgrade`, `xhttp`;
- `flow=xtls-rprx-vision`, шифрование VLESS (`encryption=`), `pqv` для REALITY,
  `pcs` (SHA-256 сертификата сервера) для самоподписанного TLS.

## Установка

Телефон должен быть в той же сети Wi-Fi, что и компьютер (или подключён по USB).
Его адрес можно посмотреть в сведениях о сети Wi-Fi на телефоне или в списке устройств
роутера. Выполните:

```sh
curl -L https://github.com/HunterEwok/aurora-xray-tun/releases/latest/download/aurora-xray-tun.tar.gz | tar xz
cd aurora-xray-tun
./setup.sh 'vless://UUID@ваш.сервер:443?type=tcp&security=reality&pbk=...&sid=...&sni=...&flow=xtls-rprx-vision#vps' 192.168.1.50
```

Последний параметр — адрес телефона. Без него скрипт идёт на `192.168.2.15`: такой
адрес у телефона, подключённого по USB.

Ссылку берите в одинарные кавычки: в ней есть `&` и `#`. В архиве скрипты и готовые
подписанные пакеты Xray-core для обеих архитектур (`rpm/`, суммы в `rpm/SHA256SUMS`).

`setup.sh` делает конфиг из ссылки, узнаёт архитектуру телефона и берёт нужный пакет
(проверяя SHA-256), копирует всё в `~/xray-tun` на телефоне, кладёт `on.sh` и `off.sh` в
домашнюю папку и добавляет команды `on` и `off` в `~/.bashrc`, ставит пакет через
установщик Авроры, запускает сторожа (см. ниже), включает туннель и показывает, с какого
адреса телефон выходит в интернет. Этот адрес должен совпасть с адресом вашего сервера
(или с адресом, через который сервер выходит в интернет).

SSH спросит пароль `defaultuser`, а `devel-su` — пароль root (тот же пароль из режима
разработчика); пароль root нужен только здесь. Чтобы не вводить пароль SSH, можно один
раз выполнить `ssh-copy-id defaultuser@<адрес телефона>`. Конфиг с вашим UUID остаётся
только на телефоне.

| Переменная | Значение |
|---|---|
| `IPV6=1` | заворачивать в туннель и IPv6 (на телефоне пока не проверялось) |

Поменялась ссылка: просто запустите `./setup.sh` с новой.

## Управление

Прямо на телефоне, в «Терминале» (он открывается в домашней папке):

```sh
on      # включить
off     # выключить
```

Пароль не нужен. Короткие команды `on` и `off` добавляет в `~/.bashrc` скрипт
`setup.sh`, они начинают работать в новом окне «Терминала». Без них то же
самое: `sh on.sh` и `sh off.sh`. `sh` перед скриптом обязателен: `/home` смонтирована с
`noexec`, поэтому `./on.sh` не сработает.

### Сторож

Поднимать TUN может только root, поэтому туннелем управляет сторож: маленький скрипт,
который работает от root в фоне. Он включает туннель, пока есть файл `~/xray-tun/on`, и
выключает, когда файла нет. `on` создаёт этот файл, `off` удаляет, root для этого не
нужен. Ещё сторож сам перезапускает туннель при смене сети (Wi-Fi ↔ мобильная) и если
Xray упал. Его журнал: `/run/aurora-xray-tun.watch.log`.

Сторож запускается при установке. После перезагрузки телефона его нет, и
первый `on` один раз спросит пароль root, чтобы запустить его снова. Остановить сторожа
вместе с туннелем: `devel-su sh ~/xray-tun/vless.sh unwatch`.

## Собрать самому

Готовые пакеты собирает GitHub Actions из этого репозитория (`.github/workflows/release.yml`).
Собрать самому стоит ради своей версии Xray-core, своего имени пакета или своего ключа
подписи. Нужны Docker (на Mac — Docker Desktop) и около 3 ГБ на диске.

```sh
git clone https://github.com/HunterEwok/aurora-xray-tun
cd aurora-xray-tun
./build.sh                 # пакет для armv7hl в out/
ARCH=aarch64 ./build.sh    # для 64-битных телефонов, ARCH=all — оба
```

Первая сборка идёт долго: Docker собирает образ с Go и кросс-компиляторами и один раз
скачивает Aurora Platform SDK (около 600 МБ, с sdk-repo.omprussia.ru). Ключи подписи
скачиваются сами (см. «Ключи подписи»). Пакет из `out/` у
`setup.sh` в приоритете перед готовым.

| Переменная | Значение |
|---|---|
| `ARCH=armv7hl\|aarch64\|all` | архитектура (по умолчанию `armv7hl`) |
| `APP_ID=...` | другое имя пакета (тогда и `APP_ID=... ./setup.sh ...`) |
| `XRAY_VERSION=v...` | другая версия Xray-core (тег из github.com/XTLS/Xray-core) |

Архитектуру телефона можно узнать так: `ssh defaultuser@<адрес телефона> rpm -q --qf '%{ARCH}\n' glibc`.
У R570E ядро 64-битное, но система 32-битная, поэтому там `armv7hl`.

### Ключи подписи

`build.sh` подписывает пакет публичной тестовой парой ОМП для профиля Regular
(«Noname developer, for testing only»). ОМП публикует её для всех разработчиков, это не
секрет. Телефон принимает пакеты с такой подписью только в режиме разработчика.

Скрипт скачивает оба файла в `keys/` сам и сверяет SHA-256:

| Файл | SHA-256 |
|---|---|
| [`regular_key.pem`](https://developer.auroraos.ru/content-images/dev-documentation/regular_key.pem) | `5d0d87728ddb719dcd506635b093efd2da303a990e0085c885d53aeb5282d6c5` |
| [`regular_cert.pem`](https://developer.auroraos.ru/content-images/dev-documentation/regular_cert.pem) | `2ad68fead24760f9dc2a56274c2fd77ee3426ecdc7360890af459d81b8e2af86` |

Сайт ОМП иногда не отдаёт файлы скриптам (ответ 403). Тогда скачайте их в браузере и
положите в `keys/` под теми же именами. Свои ключи (например, выданные ОМП) кладите
туда же под этими именами: если файлы уже есть, скрипт ничего не скачивает. В git ключи
не попадают.

## Новый релиз

Тег вида `v1.0.0` в этом репозитории запускает сборку: Actions собирает оба пакета,
архив `aurora-xray-tun.tar.gz` и `SHA256SUMS` и публикует их в Releases. Если сайт ОМП не
отдаёт ключи раннеру GitHub, их можно положить в секреты репозитория
`AURORA_REGULAR_KEY` и `AURORA_REGULAR_CERT`.

## Ограничения

- Нужны режим разработчика и root. В «Настройки → VPN» туннель не попадает.
- После перезагрузки телефона первый `on` спрашивает пароль root: запускать сторожа
  при загрузке можно только правкой системных файлов, а этот набор их не трогает.
- По умолчанию туннелируется только IPv4. IPv6 телефона идёт напрямую, поэтому сайты,
  открытые по IPv6, видят ваш настоящий адрес. Сборка с `IPV6=1` заворачивает и IPv6,
  но на телефоне это ещё не проверялось.
- Пакет подписан общим тестовым ключом. Для установки без режима разработчика нужен
  свой ключ от ОМП, а для «Настроек → VPN» нужен ещё и профиль Extended и плагин connman.

## Удаление

```sh
./setup.sh remove 192.168.1.50
```

Останавливает сторожа и туннель (тогда спросит пароль root), удаляет пакет через
установщик Авроры, папку `~/xray-tun`, файлы `~/on.sh`, `~/off.sh` и команды `on` / `off`
из `~/.bashrc`.

## Если не работает

- Журналы на телефоне: `sh ~/xray-tun/vless.sh log` (Xray и сторож).
- «пакет не установлен»: проверьте, что включён режим разработчика, и запустите
  `./setup.sh` ещё раз.
- «не удалось узнать адрес»: телефону недоступен DNS через HTTPS
  (1.1.1.1 и 8.8.8.8). Укажите в ссылке IP-адрес сервера вместо имени.
- Сайты не открываются, а Xray работает: проверьте ссылку в другом клиенте (например,
  v2rayN или Hiddify). Скорее всего, не совпадает какой-то параметр.

## Лицензии

Xray-core распространяется под MPL-2.0. Пакеты в релизах собраны без изменений из его
исходников, тег указан в `build.sh` (`XRAY_VERSION`), исходники:
https://github.com/XTLS/Xray-core. Кода Xray в этом репозитории нет: сборка скачивает
его исходники.
